## 2. How the system works

One Railway container runs the FastAPI server, the scheduler (every 10 minutes) and all workers.
State is JSON files on a 49 GB volume plus a small SQLite file. The site (Next.js on Vercel) proxies
to it.

| Stage | Input → output | Model / service | Checks that exist | Retry / recovery | Person involved | Status |
|---|---|---|---|---|---|---|
| Source monitoring | series pages → chapter list, release dates, first-seen time | HTTP scrape | status per mirror | every 6 h | adds series | Working; **stopped whenever autopilot was off** (fixed on branch) |
| Chapter detection | watchlist → "next chapter" per series | — | paywall wait (24 h Asura) | — | — | Working |
| Ingest: scrape | chapter URL → page images | HTTP | short-chapter warning | none; no timeout | — | Working; re-runs on every pass |
| Split | pages → panel crops | geometry + YOLO; ≤60 vision checks (3.5-flash) | fallback to legacy splitter | re-runs on every pass, uncached | — | Working |
| Describe | crop → text, description, speaker | gemini-3.8-flash, 1 call per panel | per-panel cache by image + prompt | 4 attempts | — | Working; cache blocked chapters after any deploy (fixed on branch) |
| Script | descriptions → narration | 3.8-flash: beat sheet, ~9 units, critique, ≤3 rewrites | critique; chatbot-phrase guard | 3 attempts; no checkpoint | — | Working; rewrites never re-checked (fixed on branch) |
| Voice | lines → mp3 | gemini-3.8-flash-tts, 1 call per line | content-hash cache | 5 attempts | — | Working; a failed line could brick the chapter (fixed on branch) |
| Match / timeline | lines → panels, timing | embeddings; DP aligner, order kept | validator rules (advisory) | — | board edits | Working |
| Crops / framing | shot → crop box | 2.5-flash crop planner; 3.8-flash subject box | crop gate | failures fall back to full panel | — | **Crop planner broken in production since Nov 8** (fixed on branch) |
| Render | segments → clips → export | ffmpeg / OpenCV, in the web process | timeline errors block | resume ≤2 after restart | presses Render | Working; 8 of 40 queue items failed "error opening encoder" (not root-caused) |
| Compilation | chapter exports → merged video | ffmpeg stream copy | order, gaps, same series at request time | — | builds range | Working; **every join has a timestamp fault** (fixed on branch) |
| Packaging | script → title, description, tags, thumbnail | 3.5/3.8-flash; local thumbnail | limits, duplicate title | every 6 h | edits, approves | Working; not versioned |
| Scheduling | queue → slot | Posting Review sheet gate | approved, unchanged, metadata valid | missed slot moves | fills the sheet | Working |
| Publishing | export → YouTube | Upload-Post | request status | 3 attempts; **no recovery after a restart** (fixed on branch) | — | Working |
| Verification | post → link | Upload-Post status only | — | — | — | Partial: YouTube itself is never asked |

## 3. Findings and fixes

Ranked by the order in the brief: wasted spend, lost work, content failures, release bottlenecks.
"Fix" entries are on the branch with tests unless marked otherwise.

### A. Wasted spend

| # | Finding (evidence) | Root cause | Fix | Verified |
|---|---|---|---|---|
| A1 | 48% of spend is thinking tokens; a 79-token test question spent 602 thinking tokens for an 80-token answer | no call set a thinking level | image calls ask for `low` thinking; crop planner gets a thinking budget of 0 (`usage.thinking_level`, `shot_planner.CROP_THINKING_BUDGET`) | A/B on real panels (section 4). Saving is projected until a chapter runs on the new code |
| A2 | Flex was served on 1 call in ~2,350; each refused request was repeated on Standard, so every call was made twice at full price | Google refuses Flex instantly ("high demand"); the code fell back silently; pooled calls dropped the requested tier | breaker: after 3 refusals Flex is skipped for 10 minutes; the tier now rides into worker threads; requested vs served tier is logged | unit tests; Flex itself still unavailable, so no dollar saving today |
| A3 | 16% of spend had no chapter; no call had a stage | job id was thread-local and unset for packaging and site requests; no stage field | every call logs `stage` and `project`; packaging runs under `pkg:<chapter>`; `/api/spend` reports by stage | unit tests |
| A4 | Ten chapters failed on HTTP 402 (Oct 29–Nov 3), each retried, ten series blocked | an account failure (credits ran out) was counted against each chapter | account failures: no strike, all starts held 30 minutes with the reason, then one retry | `test_failure_kinds.py` |
| A5 | Death Knight 95 failed twice on "cache is stale" | cache keys include code-file hashes, so any deploy made unfinished work stale; autopilot retried a failure that cannot change | code-only differences count as current (`CACHE_CODE_STRICT=1` restores); deterministic failures block at once | `test_cost_controls.py`, `test_failure_kinds.py` |
| A6 | A failed or paused voice line left the chapter failing "voice cache is edited" on every retry | lines still recording when one failed were written but never registered | every finished line is registered; unregistered leftovers are removed and re-made free from the voice cache | `test_cost_controls.py` |

### B. Lost or repeated work

| # | Finding | Fix | Verified |
|---|---|---|---|
| B1 | The stalled-job sweep rewrote any chapter still running 30 minutes after it was queued as "error"; a restart then dropped it | the sweep touches render records only | code review + suites |
| B2 | Chapters written off at startup stayed "queued" in autopilot's ledger: never retried, shown "in line" for good | written-off jobs fail in the ledger | code review + suites |
| B3 | The same job could be queued twice (double Resume), and ran again after finishing | one queue entry per job | code review + suites |
| B4 | A publish cut off by a restart stayed "posting" for good; pressing Post again uploaded a second copy | the upload id is stored before sending; a retry asks Upload-Post first; orphaned records can be restarted | `test_durable_upload.py` (assumes Upload-Post answers status by request id, as the existing code already relies on) |

### C. Content failures

| # | Finding | Fix | Verified |
|---|---|---|---|
| C1 | **Crop planner broken since Nov 8.** An unpinned rebuild pulled google-genai 3.0.0, whose default API version refuses JSON mode: every crop request failed and each shot silently used the full panel | all SDK clients request `v1beta`; production packages pinned (`deploy/requirements.txt`) | reproduced and fixed against the live API |
| C2 | Every merged video has duplicate timestamps at each chapter boundary (30 of 30 exports checked fail the studio's own QA; reproduced on test clips) | new join: cut each inner chapter exactly at the keyframe of its end card, join like a chapter's own clips (pictures copied, sound encoded once) | clean on studio-style test clips; on a real 62-minute production export it runs and the total adds up (212 s). **Existing merged files keep the faults already inside them.** Not yet tested on real single-chapter exports (none remain on the volume) |
| C3 | Nothing checked a compilation's order, encoding or total length | checked before and after joining; output untouched on failure | `test_stitch_checks.py`, incl. "old compilation + new chapter" |
| C4 | Rewritten script units were never re-checked, so "needs_review" (30 of 36 chapters) carried no information | one re-check call over the rewritten units; outcome is then "clean" or lists what is still wrong | `test_narrative_reliability.py`; not yet run on a real chapter |
| C5 | No report was read when a video was approved or posted | `release_gate.py`; off by default, reports in `/api/scorecard`; `RELEASE_GATE=critical` blocks posting | `test_release_gate.py` |

| # | Finding | Fix | Verified |
|---|---|---|---|
| D1 | No series page was read for 8 days: the read sat behind "autopilot is on" | sources are read whether or not autopilot may start work | `test_failure_kinds.py` |

### Found, not fixed (ranked)

1. **Release rule conflict** (owner decision): the Nov 8 rule (merges never overlap posted videos, 7 new chapters each) yields about one release every two days from 23 weekly series; the cumulative model in the brief yields about three a day. See section 6.
2. Manual merges ignore chapters already posted or uploading (`_range_ctx`), so a chapter can post alone and inside a merge. Fix depends on decision 1.
3. `_propagate_series_defaults` rewrites title, description and targets of queued and posted videos; with several channels it would re-route queued videos.
4. Multi-channel is partial: per-video targets exist, but schedule, sheet tab, title template, brand constants, voice and the Upload-Post profile are global. No channel registry.
5. Only one chapter is made at a time (one ingest worker, one render lock); module-level state in the scraper, narrator and renderer prevents more.
6. A paused chapter holds the only worker.
7. Speaker labels are unstable: two runs at the same setting disagreed on 10 of 24 panels.
8. 8 of 40 render-queue items failed with "error while opening encoder"; one chapter was re-added 4 times.
9. Approvals record no reviewer; the edit log is deleted on re-run; review time is not recorded.
10. Renders run inside the web process.
11. Export retention (7 days) runs only from a page the new site never opens; trash and leftover sweeps are not on the scheduler.
12. Thumbnail badge range is painted over the previous one instead of drawn from the stored range (branch `fix/merge-thumb-badge` exists, unpushed).

## 4. Quality benchmark

### Definitions

| Dimension | Unit | How it is measured today | Acceptance | Critical defect (blocks release) |
|---|---|---|---|---|
| Story fidelity | script unit (scene) | editor flags per chapter; open flags after re-check | 0 open invented-fact / wrong-order / missed-beat flags | any open one (`script_unresolved`) |
| Speaker attribution | dialogue line | not measured against truth | — | none yet |
| Pronunciation | name | not measured; no pronunciation data exists | — | none yet |
| Scene coverage, order | panel / unit | validator rules; order kept by the aligner | 0 high findings | not blocking (precision unknown) |
| Image–narration alignment | timeline row | validator (rules; model passes are manual and paid) | — | not blocking |
| Audio / render | export | final-media QA | pass | `media_failed` |
| Compilation | merged export | piece order, encoding, total length; QA decode | all pass | check failure stops the build |
| Metadata / thumbnail | video | `validate_publish`; range in title | pass | already blocks |
| First-pass acceptance | export | approved with no send-back | ≥ 90% | — |
| Manual review minutes | release | **not recorded** | — | — |
| Completion / timeliness | chapter / video | job outcomes; scorecard | ≥ 90% within 48 h | — |

### Results

- **Script, 59 chapters:** 93 editor flags (1.58 a chapter): 61 invented facts, 18 style, 8 spoiled reveals, 5 missed beats, 1 redundancy. 53 chapters had at least one. 91 units were rewritten; none was re-checked. This is a model's review, not a human-verified error rate.
- **Media, 96 exports:** 66 pass (68.8%). All 30 failures are merged videos with timestamp faults at joins.
- **Timeline, 59 chapters:** 85 high-severity findings (34 chapters). Precision unmeasured.
- **Gate in report-only mode, 96 exports:** 2 clear, 62 need a look (rewrites never re-checked), 32 would be held (30 media, 6 open script flags).
- **Known-failure set:** 13 past failures with chapter and date are listed in the quality audit notes (lion-dance costumes narrated as monsters, hero named "Yu Shin", "C-Cursed" voiced "see, Cursed", missing explosion panel, wrong chapter's images, stale merge boards, thumbnail badge). They are not yet committed as regression fixtures.

### A/B tests run for the cost changes (recorded, $0.22)

| Change | Sample | Result |
|---|---|---|
| Describe at low thinking | 24 panels, Mount Hua 186 | text read from the panel identical on 24 of 24; thinking 269 → 0 tokens a panel; speaker labels differed from stored on 10 panels |
| Describe at default, second run | same 24 panels | speaker labels differed from stored on the same number (10) — so the difference above is normal variation |
| Crop planner, thinking budget 0 | 12 boxes | mean overlap with stored boxes 0.81, all ≥ 0.5 (default re-run: 0.86, 5 of 6); thinking ~1,880 → 0 tokens a call |

### What the benchmark cannot say yet

There is no human-labelled ground truth for fidelity, speakers or image placement, so no claim of
90% or 98–100% quality can be made. The scorecard gives the automated side; calibration needs a
person to label a sample (suggested: 5 chapters, every unit marked right/wrong, every placement
marked right/wrong) so the editor's and validator's precision and recall can be computed.

## 5. Cost

Per chapter, from the usage log (26 chapters, stage inferred from model and prompt size):

| Stage | Calls | Cost | Of which thinking |
|---|---|---|---|
| Image calls: describe + subject framing | 229 | $0.688 | $0.312 |
| Script (beat sheet, units, critique, rewrites) | 13 | $0.190 | $0.112 |
| Crop planner | 40 | $0.172 | $0.154 |
| Voice | 87 | $0.125 | 0 |
| Split checks | 12 | $0.059 | $0.046 |
| Embeddings | 197 | $0.002 | 0 |
| **Total** | | **$1.24** | **$0.62** |

- **Projected after the branch:** median **$0.73** (range $0.52–$1.16); 25 of 26 chapters under $1, none under $0.50. Script thinking is kept. The re-check adds about $0.01.
- **To reach $0.50:** fold the subject box into the describe call (about −110 calls, −$0.18), then the floor is voice ($0.13) plus image input tokens. Flex or batch pricing would halve the model part if Google serves it.
- **Daily:** 4 new chapters a day ≈ $2.90 projected ($4.96 today), inside the $5–$7 target. The cap is $7.50 a day; autopilot's own budget is $6.
- **Failed attempts** are inside each chapter's figure. Calls that fail before a response are not logged; whether Google bills them is unknown.
- **Reused chapters** in a merged video cost nothing and are not counted as new output. A merge costs CPU only (212 s for 2 hours of video with the new join).
- **Fixed costs not measured here:** Railway bill, Upload-Post plan, Vercel. The Railway invoice was not available to this audit; the $10/month target is unverified.

## 6. Release volume and calendar

- 23 series, roughly one chapter a week each ≈ 3.3 new chapters a day.
- Rule of Nov 8 (no overlap, 7 new chapters per merge): about 0.5 releases a day.
- Cumulative rule of the brief (previous compilation + new chapter): about 3.3 releases a day — the only route to 3–4 a day from the current series. It re-posts earlier material, which the Nov 8 rule forbade. **This needs the owner's decision.**
- What exists: series subscriptions, 6-hourly detection, first-seen time, release dates (day precision), gap detection, per-series made/posted-through, planned slots, the sheet gate.
- Missing: a per-chapter record tying detection → made → approved → live with a deadline; verified live time from YouTube; a channel on each series.
- 12 of 50 published videos cannot be timed (11 have no watchlist series for their link).

1.6 GB, pages 0.8 GB, trash 0.7 GB, audio 0.65 GB, split lab 0.56 GB.

- The two largest folders are the queued merges (1.2 and 1.3 GB).
- Unbounded today: voice cache, job records, usage log, source revisions, leftovers of interrupted merges.
- Posted exports are deleted only after a size + MD5 match in Drive; archived chapters are deleted 14 days after posting without a Drive check of the non-video files.
- No deletion was added in this audit: retention rules need the owner's sign-off first (crops and revisions are the bulk and are needed to rebuild a chapter).

## 9. Deployment and rollback

- Branch `feat/audit-fixes-20261113`, two commits, 481 tests + 22 script suites passing.
- Deploy with the job bar empty: the image is rebuilt (pinned packages) and the server restarts.
- After deploy: make one chapter, then read `/api/spend` (by stage), `/api/scorecard`, and the chapter's `critique.json` (`verified`).
- Rollback: `git revert` the two commits and push; or per feature without a deploy:

| Feature | Switch |
|---|---|
| Low thinking on image calls | `VISION_THINKING_LEVEL=default` |
| Crop planner thinking | `CROP_THINKING_BUDGET=` (empty) |
| Re-check of rewrites | `CRITIQUE_VERIFY=0` |
| Code-only cache rule | `CACHE_CODE_STRICT=1` |
| Clean join | `STITCH_ENGINE=copy` |
| Release gate | `RELEASE_GATE=off` (default) |
| Flex breaker | `FLEX_TRIP=1000000` |
